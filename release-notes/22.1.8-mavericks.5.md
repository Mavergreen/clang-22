C++ and Cocoa now mix safely. A C++ exception that crossed between your code and Cocoa (a `try` around a
Cocoa call that raises, an `@catch` around C++ that throws) or the system's own C++ used to crash the
program with "pointer being freed was not allocated", because the toolchain carried a second copy of the
C++ runtime's ABI library beside the system's. Programs built with clang22, and libcxx22, now use the
system's `/usr/lib/libc++abi.dylib` alone. Recaulk 20261019.1 fills in what 10.9's lacks.

Weak symbols now coalesce across a program and its libraries on 10.9: the linker writes them the way
10.9's loader needs. Before, a C++ class's type information could differ between a program and a
library, so a `catch` in one missed an exception of that class thrown in the other.

A C++ program clang22 builds now depends on `/usr/lib/libc++abi.dylib` as well as `libSystem`; both are
part of every macOS since 10.7. One case still fails on 10.9 to 10.13: catching an `__int128`, which
10.9's runtime cannot align.
