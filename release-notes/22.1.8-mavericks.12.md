A program that brings its own static C++ runtime now links. rusty_v8's prebuilt archive, which
codex-cli links, is one: it carries its own libc++abi, and the link failed with duplicate symbols
(`__cxa_uncaught_exceptions`, the pointer catch vtables). Recaulk, which fills in what 10.9 lacks, is
now linked after everything a program names, so it fills only what is still missing and a program's
own definitions always win.

One consequence: a link that names the system's C++ library itself (`-lc++` or `-lc++abi`) now takes
the pointer and member-pointer catch vtables from it, so its own `catch` clauses follow 10.9's rules
again, as before 22.1.8-mavericks.9. Programs that leave the C++ library to clang++, and programs linked
against libcxx22, keep LLVM 22's rules.

Both toolchain packages now require Longboat's Mac OS X 10.9 SDK (`sdk109`), not just Longboat, and
refuse to install without it. Install Longboat, run `longboat sdk install 10.9`, then the package.
